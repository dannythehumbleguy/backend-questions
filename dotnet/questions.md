>## Что такое deadlock?
> Частота: средне

**Deadlock** - взаимная блокировка ресурсов потоками.
```csharp
// Thread 1
lock(A)
{
    lock(B)
    {
        
    }
}

// Thread 2
lock(B)
{
    lock(A)
    {
        
    }
}
```
**Поясление**: Пока **Thread #1** что-то делал, **Thread #2** заблокировал ресурс B, немного позднее **Thread #1** заблокировал ресурс A и пытается заблокировать ресурс B, 
к сожалению это никогда не произойдет, т.к. **Thread #2** освободит ресурс B лишь после того как заблокирует ресурс А.

>## Какие есть примитивы синхронизация потоков?
> Частота: средне

**Примитивы синхронизации:**
- **lock (Monitor)** - предоставляет монопольный доступ к ресурсу в рамках приложения.
- **Mutex** - предоставляет монопольный доступ к ресурсу в рамках приложения или опереционной системы.
- **Semaphore** - ограничивает кол-во потоков, которые одновременно имеют доступ к ресурсу.
- **Interlocked** - предоставляет атомарные операции для переменных, в основном числовых, доступных нескольким потокам.

>## Что такое ValueTask<T> и зачем он нужен?
> Частота: часто

**ValueTask\<T>** - это обертка над Task\<T> или T, которая является структурой. Нужна она для того, чтобы избавиться от лишних аллокаций Task\<T> на куче.

>## Когда используем ValueTask<T>?
> Частота: средне

- Когда часть возвращений из метода происходит синхронно, а часть асинхронно.
- Когда нужно создавать очень много Task<T> под коротко-живущие задачи(десятки тысяч).

>## Что делать с ValueTask<T> не надо?
> Частота: редко

```csharp
// Given this ValueTask<int>-returning method…
public ValueTask<int> SomeValueTaskReturningMethodAsync() {...};

// GOOD
int result = await SomeValueTaskReturningMethodAsync();
// GOOD
int result = await SomeValueTaskReturningMethodAsync().ConfigureAwait(false);
// GOOD
Task<int> t = SomeValueTaskReturningMethodAsync().AsTask();

// WARNING: storing the instance into a local makes it much more likely it'll be misused,
// but it could still be ok
ValueTask<int> vt = SomeValueTaskReturningMethodAsync();

// BAD: awaits multiple times
ValueTask<int> vt = SomeValueTaskReturningMethodAsync();
int result = await vt;
int result2 = await vt;

// BAD: awaits concurrently (and, by definition then, multiple times)
ValueTask<int> vt = SomeValueTaskReturningMethodAsync();
Task.Run(async () => await vt);
Task.Run(async () => await vt);

// BAD: uses GetAwaiter().GetResult() when it's not known to be done
ValueTask<int> vt = SomeValueTaskReturningMethodAsync();
int result = vt.GetAwaiter().GetResult();
```

>## Почему нельзя использовать **async void**?
> Частота: часто

- Невозможно следить за состоянием, так как нет доступа к экземпляру Task.
- Нельзя дождаться выполнения асинхронного метода.
- Нельзя отловить исключение от такого методе.
- Исключение будет выброшено в основной поток исполнения.

## **Почему нельзя вызывать await в lock?(2)**
> Частота: часто

Все **не Slim** примитивы синхронизации потоков блокируют текущий поток, пока ресурс не будет освобождён, что нарушает принцип освобождения потоков во время ожидания.  
**Как решить?**  
```csharp
private static readonly SemaphoreSlim _semaphore = new SemaphoreSlim(1, 1);

private static async Task Method1Async()
{
    await _semaphore.WaitAsync(); // Асинхронно ждем освобождения семафора
    try
    {
        await Task.Delay(1000); // Имитация работы с ресурсом
    }
    finally
    {
        _semaphore.Release(); // Освобождаем семафор после завершения работы с ресурсом
    }
}
```

>## Что такое IO Bound & CPU Bound?
> Частота: средне

**CPU Bound** - задача выполняется на процессоре, от него же и зависит время её выполнения, соответственно поток занимается.
**IO Bound** - задача выполняется внешним устройством, для чего требуется ожидание ответа потоком процессора.

>## Отличие Reference & value types?
> Частота: часто

**Тип ссылочный** - значение переменной содержит ссылку на экземпляр.  
**Тип значений** - значение переменной содержит непосредственно экземпляр.

**Что и где хранится?**
- Классы всегда хранятся на куче.
- Структуры имеет возможность хранится на стеке, если платформа может определить, что они не будут использованы после очистки места в стеке, где они были выделены. Например экземпляр структуры объявленный и используемый только в теле метода, может быть выделен на стеке.

>## Что такое CLR?
> Частота: редко

общеязыковая среда выполнения.  
**Основные обязанности CLR:**
- JIT-компиляция, её задача состоит в том, чтобы приобразовывать CIL код в машинный.
- Система типов, отвечает за контроль типов и их совместимость.
- Обработка исключений на уровне пользовательской программы и среды.
- Управление памятью(сборка мусора)

>## Как работает Grabage Collector?
> Частота: редко

**Garbage Collector** - часть CLR, которая отвечает за управление памятью программы.
1. **Маркировка** (mark phase) - определения достижимых с корня объектов, не достижимые будут помечены к удалению.
2. **Чистка** (sweep phase) - объекты помеченные на первой фазе удаляются.
3. **Сжатие/Дефрагментция** (compact phase) - CLR определяет нужно ли сжатие и если нужно, то все объекты поближе к друг другу в начало кучи.

>## Плюсы GC
> Частота: редко

- Автоматическое выделение и очистка памяти, что позволяет разработчику не думать о том:
    - Где в куче будут размещены объекты
    - Какие объекты уже можно удалить
    - Когда и как нужно производить дефрагментацию
- Обеспечивает безопасность памяти, что позволяет разработчику не думать о том:
    - Какая область памяти, какому объекту пренадлежит
    - Является ли ссылка ссылка на экземпляр еще актуальной

>## Какие режимы работы GC существуют?
> Частота: средне

- **Режим рабочей станции** - позволяет минимизировать задержки при очистке памяти, чтобы предоставить пользователю хорошую отзывчивость приложения.
- **Режим сервера** - позволяет максимизировать производительность, но возростает потребление ресурсов

>## Какие есть условия вызова сборки мусора?
> Частота: редко

- Мало памяти
- Превышен бюджет выделения памяти для объекта (потом он увеличивается)
- Ручной вызов GC.Collect

>## Что такое “stop the world”?
> Частота: средне

**Stop the world** - ситуация при дефрагментации кучи, когда нельзя выделить память и все приложение останавливается.

>## Как уменьшить вероятность сборки мусора в  небольшой блоке кода?
> Частота: редко

Использовать **GC.TryStartNoGCRegion** и **GC.EndNoGCRegion.**

>## Что такое неуправляемые ресурсы?
> Частота: средне

**Неуправляемые ресурсы** (unmanaged resources) — это ресурсы, которые находятся **вне контроля среды CLR**. Например файлы, которые являются частью операционной  системы.
>## В чем отличие IDisposable и Finalizer?
> Частота: редко

**Метод .Dispose()** вызывается разработчиком, когда нам нужно освободить неуправляемые ресурсы. Конечный .Dispose() вызовет системные функции ОС, сам GC в процессе никак участвовать не будет.  
**Когда полезен:**
- Детерминированность - ресурсы будут очищены сразу после выполнения метода, когда будет вызван финализатор - неизвестно.
- Производительность - объекты с финализаторами требуют дополнительных шагов при очистке памяти. У такого объкта при первой очистке будет сначала вызван финализатор и лишь при повторной объект будет очищен.  
**Финилизатор** вызывется GC, когда он определяет объект, как подходящий к очистке.  
**Когда полезен:**
- Тяжело контролировать жизненный цикл объектов, использавание объктов в сложных асинхронных/многопоточных сценариях.
- Как дополнительный способ защитится от не вызова .Dispose().
